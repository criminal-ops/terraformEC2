Install Terraform
Run each command separately.

Step 1 — Update package information
sudo apt update


Step 2 — Install required tools
sudo apt install -y wget curl gpg unzip


Step 3 — Add the official Terraform package repository
wget -O- https://apt.releases.hashicorp.com/gpg | sudo gpg --dearmor -o /usr/share/keyrings/hashicorp-archive-keyring.gpg


echo "deb [arch=$(dpkg --print-architecture) signed-by=/usr/share/keyrings/hashicorp-archive-keyring.gpg] https://apt.releases.hashicorp.com $(grep -oP '(?<=UBUNTU_CODENAME=).*' /etc/os-release || lsb_release -cs) main" | sudo tee /etc/apt/sources.list.d/hashicorp.list


Step 4 — Install Terraform
sudo apt update
sudo apt install -y terraform


Step 5 — Verify the installation
terraform -version


If a Terraform version is displayed, installation is successful. You can also check its location:
which terraform


Usually, the output is /usr/bin/terraform.
4. Install or repair AWS CLI
You previously encountered an AWS CLI error, so check the installation rather than assuming it works.

First, try:
aws --version


If it shows a version such as aws-cli/2.x.x, continue to Step 5.

If it says command not found or Unable to load data for: cli, reinstall/update it using the following commands:
cd ~


sudo ./aws/install --update


If the command says that the installer file does not exist, use this complete installation sequence instead:
cd ~


sudo rm -rf /usr/local/aws-cli


sudo rm -f /usr/local/bin/aws


curl "https://awscli.amazonaws.com/awscli-exe-linux-x86_64.zip" -o awscliv2.zip


unzip -o awscliv2.zip


sudo ./aws/install


Then verify:
aws --version


Expected result: a line beginning with aws-cli/2....

If the same loading error remains, stop here and fix the CLI before continuing; Terraform needs working AWS credentials and authentication.
5. Get the AWS credentials for your account
This is the part that changes according to which AWS account or lab account you are using.
Where do you get the keys?
Open the AWS Console: Open AWS Console.









Step 1: Open IAM

Search for IAM in the AWS Console and open it.












Step 2: Select your IAM user

Open Users, select the user authorized for your practical, and open Security credentials.












Step 3: Access keys

Find Access keys and choose Create access key if your account allows it. Follow the prompts and securely save both the Access Key ID and Secret Access Key.



Important:
- If your college gives you AWS Academy or temporary lab credentials, use the credentials and instructions provided by your instructor. IAM access-key creation may be disabled in these accounts.
- If you have only an AWS root account, do not create root access keys just for this practical. Use an authorized IAM identity or your college's approved credentials.
- The Secret Access Key is normally shown only when it is created. Never share either key with anyone or paste it into main.tf, GitHub, or your practical report.
Configure your keys in Ubuntu
Run:
aws configure


It will ask four questions:
AWS Access Key ID [None]: ENTER_YOUR_ACCESS_KEY_ID
AWS Secret Access Key [None]: ENTER_YOUR_SECRET_ACCESS_KEY
Default region name [None]: ap-south-1
Default output format [None]: json


Replace the first two values with your own credentials. Type ap-south-1 as an example region; you can choose a different region.

Verify that AWS authentication works:
aws sts get-caller-identity


If successful, it displays information such as your AWS account ID and the identity being used. If you get an error, fix the credentials or permissions before continuing.
6. Create a folder for your Terraform code
Run:
mkdir -p ~/terraform-ec2


cd ~/terraform-ec2


Create the file:
nano main.tf


This opens a text editor. You will enter your Terraform code in this file.
7. Understand what changes according to your account
Before entering the code, understand these values:
Code or value	What you should do
AWS access key and secret key	Use your own authorized credentials in aws configure; do not write them in the code
AWS region	Change ap-south-1 if you want to use a different region
t3.micro	The EC2 machine type; change it only if your account, region and budget require another type
Terraform-EC2	The instance's display name; you can choose your own name
Amazon Linux AMI filter	Normally keep it as written; Terraform searches for a suitable image in the selected region
terraform apply	Creates the real resource in your AWS account

For example, these are possible AWS regions:
Region	Code
Mumbai	ap-south-1
Hyderabad	ap-south-2
US East (N. Virginia)	us-east-1
Europe (Ireland)	eu-west-1

The region must be supported by your account and have the requested EC2 instance type available.
8. Write the complete main.tf code
Copy this code into the nano editor.


terraform {
  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 6.0"
    }
  }
}

provider "aws" {
  region = "ap-south-1"
}

data "aws_ami" "linux" {
  most_recent = true
  owners      = ["amazon"]

  filter {
    name   = "name"
    values = ["al2023-ami-2023.*-x86_64"]
  }

  filter {
    name   = "architecture"
    values = ["x86_64"]
  }

  filter {
    name   = "virtualization-type"
    values = ["hvm"]
  }
}

resource "aws_instance" "my_ec2" {
  ami           = data.aws_ami.linux.id
  instance_type = "t3.micro"

  tags = {
    Name = "Terraform-EC2"
  }
}

output "instance_id" {
  value = aws_instance.my_ec2.id
}

output "public_ip" {
  value = aws_instance.my_ec2.public_ip
}



What each part does
- terraform: Specifies the Terraform provider requirement.
- provider "aws": Selects AWS and the region in which resources will be created.
- data "aws_ami": Finds a suitable Amazon Linux 2023 image in that region.
- resource "aws_instance": Defines the EC2 virtual machine to create.
- instance_type: Selects the machine size.
- tags: Gives the instance a recognizable name.
- output: Displays the created instance ID and public IP address.
If you want to change the region
Change only this line for the region:
region = "ap-south-1"


For Hyderabad, for example:
region = "ap-south-2"


The AMI lookup will search for an appropriate image in the new region. You do not normally need to change the AMI ID manually.
If you want to change the instance name
Change:
Name = "Terraform-EC2"


For example:
Name = "My-Practical-Instance"


If your mam gives a different instance type
Change:
instance_type = "t3.micro"


to the type specified in the practical, provided it is available and permitted in your account. A different type may cost more.
Save the code
In Nano:
1. Press Ctrl + O.
2. Press Enter.
3. Press Ctrl + X.
Your file is now saved as main.tf inside ~/terraform-ec2.
9. Initialize Terraform
Make sure you are in the correct folder:
cd ~/terraform-ec2


Run:
terraform init


Terraform downloads the AWS provider and prepares the working directory.

Expected result includes:
Terraform has been successfully initialized!


10. Validate the code
Run:
terraform validate


Expected result:
Success! The configuration is valid.


This checks the Terraform configuration for syntax and configuration errors. It does not create the EC2 instance.
11. Check the execution plan
Run:
terraform plan


Terraform checks what it intends to create. You should see a plan indicating that one EC2 instance will be added, typically shown as Plan: 1 to add, 0 to change, 0 to destroy.

If the command reports an error, fix it before proceeding.
12. Create the EC2 instance
Run:
terraform apply


Terraform displays the plan and asks you to confirm. Type:
yes


Then press Enter.

Wait until the operation finishes. You should see a result similar to:
Apply complete! Resources: 1 added, 0 changed, 0 destroyed.

Outputs:

instance_id = "i-xxxxxxxxxxxxxxxxx"
public_ip = "..."


The actual ID and IP will be different for your instance.

This is the step that creates the actual EC2 instance in your AWS account. Installing Terraform or running terraform init alone does not create it.
13. Verify the EC2 instance in AWS Console









Step 1: Open the EC2 Console.











Step 2: Select the same region you used in main.tf. For the example above, select Asia Pacific (Mumbai).











Step 3: Open Instances → Instances and find Terraform-EC2. Confirm its state is Running.



You can also verify the instance from Ubuntu:
aws ec2 describe-instances \
  --filters "Name=tag:Name,Values=Terraform-EC2" \
  --query "Reservations[].Instances[].[InstanceId,State.Name,PublicIpAddress]" \
  --output table \
  --region ap-south-1


If you changed the instance name or region, update the filter or region accordingly.
