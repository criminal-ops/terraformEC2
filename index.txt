Step 6: Save both keys

AWS displays two values:

* Access Key ID — identifies the access key.

* Secret Access Key — the secret used to authenticate.

Download the CSV or copy both values into a secure password manager. The secret is generally shown only when the key is created.

Never share either key in a screenshot, chat, GitHub repository, or your Terraform file.

### Part 2: Configure the keys in Ubuntu (WSL)

After creating the keys, open your Ubuntu terminal (not Windows CMD) and follow these steps.

### Step 7: Check whether AWS CLI is installed

```bash
aws --version
```

If you see an output like `aws-cli/2.x.x`, continue to Step 8.

If the command is not found, install AWS CLI using the [official AWS CLI installation instructions](https://docs.aws.amazon.com/cli/latest/userguide/getting-started-install.html?utm_source=chatgpt.com).

### Step 8: Configure your credentials

Run:

```bash
aws configure
```

Enter the following when prompted:

```text
AWS Access Key ID: YOUR_ACCESS_KEY_ID
AWS Secret Access Key: YOUR_SECRET_ACCESS_KEY
Default region name: eu-north-1
Default output format: json
```

Replace the two placeholder values with the actual keys from AWS. Do not type the placeholder text literally.

AWS CLI stores the credentials in `~/.aws/credentials`, which Terraform can use automatically. AWS Command Line Interface +1

### Step 9: Verify that the keys work

Run:

```bash
aws sts get-caller-identity
```

If successful, AWS returns information containing your account ID and the IAM identity you are using.

If you get `InvalidClientTokenId`, `InvalidAccessKeyId`, or `SignatureDoesNotMatch`, check the keys you entered.

If you get `AccessDenied`, your identity may lack the necessary permissions.

### Part 3: Run your Terraform practical

Now execute your original commands in Ubuntu:

```bash
mkdir -p ~/terraform_ec2_lab
cd ~/terraform_ec2_lab
```

Create your `main.tf` file using the configuration you provided, and then run:

```bash
terraform init
terraform validate
terraform plan
terraform apply -auto-approve
```

Terraform will use your configured credentials to create the EC2 instance in `eu-north-1` (Stockholm), provided your account and IAM permissions allow it.

To verify the instance:

```bash
terraform output
```

You can also check the EC2 console by selecting the Europe (Stockholm) — eu-north-1 region.

When you have finished your practical, clean up the resources:

```bash
terraform destroy -auto-approve
```

Important: Your `terraform apply` command can create billable AWS resources. Check your account's available instance types, quotas, and pricing before proceeding. Also, `t3.micro` availability and free-tier eligibility depend on your account and current AWS terms.

### Common problems to remember for the exam

| Error                        | What to check                                                 |
| ---------------------------- | ------------------------------------------------------------- |
| Unable to locate credentials | Run aws configure.                                            |
| AccessDenied                 | Check IAM permissions for EC2 and related operations.         |
| InvalidAMIID.NotFound        | Check the AWS region and AMI lookup filters.                  |
| terraform: command not found | Install Terraform and verify its PATH.                        |
| Instance creation fails      | Check account quotas, instance availability, and permissions. |

For security, never put your access keys directly into `main.tf` or upload them to GitHub. If your college provides temporary AWS credentials or a lab-managed role, use that approved authentication method instead of creating permanent keys.

Official reference: [AWS documentation — Access keys and CLI authentication](https://docs.aws.amazon.com/cli/latest/userguide/cli-authentication-user.html?utm_source=chatgpt.com).


### Terraform EC2 Lab Practical — Step-by-Step

Follow these steps for your exact Terraform code. Since you have already downloaded the Terraform and AWS CLI tools, start with creating the AWS access keys and configuring them.

### Step 1: Create AWS access keys

* Open the [AWS Console](https://console.aws.amazon.com/?utm_source=chatgpt.com).

* Search for IAM.

* Select Users and open your assigned IAM user.

* Open Security credentials.

* Under Access keys, click Create access key.

* Select Command Line Interface (CLI) and continue.

* Create the key and securely save the Access Key ID and Secret Access Key.

If you use a college-provided AWS account, follow your administrator's instructions. Do not create access keys for the root account.

### Step 2: Configure AWS credentials in Ubuntu

Open Ubuntu (WSL) and execute:

```bash
aws configure
```

Enter your actual credentials when prompted:

```text
AWS Access Key ID: YOUR_ACCESS_KEY_ID
AWS Secret Access Key: YOUR_SECRET_ACCESS_KEY
Default region name: eu-north-1
Default output format: json
```

Verify the credentials:

```bash
aws sts get-caller-identity
```

If this displays your account and identity, continue.

### Step 3: Create and enter the directory

```bash
mkdir -p ~/terraform_ec2_lab
cd ~/terraform_ec2_lab
```

### Step 4: Set folder ownership

```bash
sudo chown -R $USER:$USER .
```

### Step 5: Create `main.tf`

Copy and run your exact configuration:

```bash
cat << 'EOF' > main.tf
terraform {
  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 5.0"
    }
  }
}

provider "aws" {
  region = "eu-north-1"
}

data "aws_ami" "ubuntu" {
  most_recent = true

  filter {
    name   = "name"
    values = ["ubuntu/images/hvm-ssd-gp3/ubuntu-noble-24.04-amd64-server-*"]
  }

  filter {
    name   = "virtualization-type"
    values = ["hvm"]
  }

  owners = ["099720109477"]
}

resource "aws_instance" "devops_server" {
  ami           = data.aws_ami.ubuntu.id
  instance_type = "t3.micro"

  tags = {
    Name        = "Terraform-DevOps-Instance"
    Environment = "Lab-Practical-7"
  }
}

output "instance_id" {
  description = "ID of the EC2 instance"
  value       = aws_instance.devops_server.id
}

output "instance_public_ip" {
  description = "Public IP of the EC2 instance"
  value       = aws_instance.devops_server.public_ip
}
EOF
```

Check the file:

```bash
ls
```

Expected output: `main.tf`

### Step 6: Initialize Terraform

```bash
terraform init
```

### Step 7: Validate configuration

```bash
terraform validate
```

Expected output: `Success! The configuration is valid.`

### Step 8: Review the execution plan

```bash
terraform plan
```

Check the planned EC2 instance creation.

### Step 9: Create the EC2 instance

```bash
terraform apply -auto-approve
```

Wait until Terraform reports `Apply complete!`.

### Step 10: View the outputs

```bash
terraform output
```

To see the full state:

```bash
terraform show
```

### Step 11: Verify the instance using AWS CLI

```bash
aws ec2 describe-instances \
  --region eu-north-1 \
  --filters "Name=instance-state-name,Values=running" \
  --query "Reservations[*].Instances[*].[InstanceId,PublicIpAddress,State.Name,Tags[?Key=='Name'].Value|[0]]" \
  --output table
```

You can also open AWS Console → EC2 → Instances and select the Europe (Stockholm), `eu-north-1` region.

### Step 12: Destroy resources after the lab

```bash
terraform destroy -auto-approve
```

This deletes the EC2 instance managed by your configuration.

Important: Your IAM identity must have the necessary permissions. Keep your credentials private, and run the destroy command after the practical to avoid ongoing charges.
